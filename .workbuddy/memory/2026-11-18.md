# 2026-11-18

## G10S-Remote：修掉两个核心 bug，建 git 仓库，重新打包 exe

### 项目速览
Windows 输入桥接器（纯 `ctypes`，零第三方依赖），把一支 2.4G 飞鼠遥控器
（VID `1915` / PID `1025`）改造成辅助输入设备。两条技术通道：

- **Raw Input**（消费者页 `0x0C/0x01`）：读 Windows 根本不翻译的键
  —— 麦克风 `0xCF`、OK `0x41`
- **低级键盘钩子** `WH_KEYBOARD_LL`：改写系统已翻译成 VK 的键
  —— 播放 `0xB3`→回车、返回 `0xA6`→Esc、菜单 `0x5D`→Ctrl+Alt+K、静音 `0xAD`→切模式

### Bug 1：语音第二下点不了结束
症状：语音开始了，第二下没反应，120 秒看门狗也不触发。

根因链：`Voice.release` 里等锁 0.8s + 两次 sleep；而松 Win 的瞬间微信输入法
开始把识别结果上屏，那些字符逐个进钩子 → `preempt_stages` → 再调 release
抢锁 → 钩子回调超 300ms → 被 Windows **静默摘除**（不报错）。之后播放/静音/
菜单键全废，只有走 Raw Input 的语音键还活着 —— 表现为"一半好一半坏"。

修复：
1. `held` 在松键**之前**置 False（否则上屏字符会触发第二条释放路径）
2. 钩子内改调新增的 `release_fast`：只发两个 keyup，**不加锁、不 sleep**

### Bug 2：静音键会真的静音并弹 OSD
根因：这支遥控器的音量/静音由 **HID 驱动层直接执行**，比键盘钩子更低一层。
钩子只能拦到它顺手生成的 `VK 0xAD`（一个"通知"），拦不住音量本身。

修复：拦截 `0xAD`（只剩驱动层一次 toggle）→ 立即用 Core Audio `SetMute`
把状态设回原值。实测 15/15、23/23 全部复位成功，音量不变。代价是音量 OSD
闪一下（几毫秒到几十毫秒），用户已接受。

### 踩过的坑（最有价值的部分）
- `IAudioEndpointVolume::SetMute` 签名是 `(BOOL, LPCGUID)` **两个参数**，
  少传第二个会读到栈上垃圾值 → 表现为"复位时好时坏"，排查了很久
- COM 对象不能跨线程：它是 STA，后台线程调用返回 `RPC_E_WRONG_THREAD`。
  用 `threading.local` 每线程各建一个 + `CoInitializeEx(MTA)`（后台线程无消息泵）
- **低级键盘钩子的回调跑在"安装它的线程"上**：主线程一忙（COM / 文件 IO /
  托盘 `Shell_NotifyIcon`），回调就排队，超 300ms 被跳过，那一次事件漏给系统
- `RIDEV_NOLEGACY` 只对 **top-level collection** 有效。这台设备的消费者页是
  复合设备子集合（`MI_03&COL02`），四种标志组合全被拒（`err=1004`）
- 「不拦 `VK 0xAD`、让系统 toggle 两次抵消」**不成立**：带 HID 来源的音量键
  shell 不会再处理一次；而 `SendInput` 注入的因为没有设备来源，shell 才会处理
  —— 这正是"注入测试能拦住、真实按键拦不住"的原因
- Windows 11 已废弃托盘气泡（`NIF_INFO`），调用不显示还白耗一次系统调用，已删

### 工程
- 建 git 仓库（`git init -b main`），**关掉 `core.autocrlf`**：否则 Windows 下
  会把 LF 全转 CRLF，改一行产生满屏 diff，回滚时也分不清哪些是真改动
- `.gitignore` 排除 `*.bmp`（20MB 调试帧缓冲）、`build/`、`dist/`、`*.log`、`*.spec`
- 提交历史：初始提交 → 后台线程/COM 修复 → 拦截+立即复位 → README 整理
- `build.bat` 原来只 `--add-data app.ico`，漏了 `app-edit.ico` / `app-watch.ico`，
  单独把 exe 拷走时托盘图标会退化成系统默认 —— 已补齐
- 新增 `tools/audiocheck.py`（读/写静音状态，`--mute/--unmute/--watch`）、
  `tools/flags_probe.py`（试探 Raw Input 标志组合）

### 未采纳的方案
把模式切换挪到 OK 键或菜单键可以彻底避开静音键的副作用，但用户明确要求
必须用静音键，接受"闪一下但音量还原"。
