# 把 Google TV 遥控器接到 Windows：语音输入 + 按键映射

> 适用：Chromecast with Google TV 遥控器（G9N9N 家族，VID `18D1` / PID `9450`）、Google TV Streamer 遥控器（GY3LE）、小米蓝牙遥控器 2 / 2 Pro（同类协议）。
> 环境：Windows 10 1809+ / Windows 11 x64，电脑自带蓝牙（BLE 4.0+）。

---

## 0. 一句话结论

**按键映射和语音输入是两条完全独立的链路，不要当成一件事做。**

| | 走的通道 | 需要什么 | 难度 |
|---|---|---|---|
| 按键（方向/OK/返回/音量/主页） | 蓝牙 HID（Consumer Control 页 `0x0C`） | Windows 键鼠栈，或 Raw Input 读原始报文 | 低～中 |
| 语音（麦克风键） | **ATVV 私有协议**（GATT + IMA ADPCM 音频流） | 自己实现协议解码 + 虚拟声卡 | 高 |

所以"蓝牙配对成功、音量键能用、但按麦克风键没反应"是**正常现象**，不是驱动坏了。麦克风键根本不发 HID 键值，它发的是 ATVV 的 `0x08` 控制报文；Windows 不认识这个协议，就把这条链路当成一条普通 BLE 连接晾着。

## 1. 先确认你手上是哪个型号

| 型号 | 外观特征 | 语音协议 | 备注 |
|---|---|---|---|
| G9N9N | 白色/彩色，14 键，Google TV 语音键 | ATVV v1.0，16 kHz | 最常见，闲鱼 15 元级 |
| GY3LE | Google TV Streamer（2024）配套 | ATVV 兼容 | 需另做适配 |
| RC001 / RC003 | 小米蓝牙遥控器 2 / 2 Pro | ATVV v1.0，16 kHz | 同类方案，兼容性最好 |

查法：`设置 → 蓝牙和设备` 看设备名；或设备管理器 → 人机接口设备 → 属性 → 详细信息 → 硬件 ID，看到 `BTHLE\DEV_18D19450...` 就是 G9N9N。

---

## 2. 为什么"配对成功但麦克风没声音"

遥控器的麦克风不是标准蓝牙音频（不是 HFP/HSP，也不是 LE Audio），Windows 的"声音设置"里永远看不到它作为输入设备。

它走的是 Google 的 ATVV（Android TV Voice）协议，挂在 GATT 上：

```
Service  AB5E0001-5A21-4F05-BC7D-AF01F617B664
  ├─ Char  AB5E0002-... (Write)              主机 → 遥控器  控制命令
  ├─ Char  AB5E0003-... (Notify)             遥控器 → 主机  音频流（IMA ADPCM 4bit）
  └─ Char  AB5E0004-... (Notify/Indicate)    遥控器 → 主机  控制状态
```

音频格式：**16 kHz / 16-bit / 单声道 / IMA ADPCM 4-bit**（压缩比 4:1），约 **50 包/秒** 才能连续供流。

想拿到声音，必须自己当"主机"完成这套握手，把 ADPCM 解成 PCM，再写进虚拟声卡。这就是网上那些项目在做的事。

## 3. 路线 A：直接用现成工具（推荐，1 小时内能用）

**MoteDeck** — `https://github.com/HZDavy/MoteDeck`，GPL-3.0，Windows 10/11 x64。

0.1.9 起支持 Google TV 款遥控器，0.2.8 为当前正式版。

### 安装

安装包已下载到本目录：`MoteDeckSetup-0.2.8-unsigned.exe`（95 MB，已对照官方 `SHA256SUMS.txt` 校验通过）

1. 双击本目录的 `MoteDeckSetup-0.2.8-unsigned.exe`（或到 Releases 下载同名文件）
2. 装到 `%LOCALAPPDATA%\MoteDeck`（未签名，首次运行 SmartScreen → 更多信息 → 仍要运行）
3. 装 **VB-CABLE**（`https://vb-audio.com/Cable/`，免费，需重启）
4. 先在 Windows 蓝牙里配对遥控器，再打开 MoteDeck → 设备页 → 扫描并添加

### 按键映射

设备页能识别后，按键页会给出对应遥控器的实物图和键位。每个键可分别配置**单击 / 双击 / 长按**，动作类型：

- 键盘快捷键（可选用驱动级注入 Interception，绕开部分应用不响应 SendInput 的问题）
- 鼠标移动 / 点击 / 滚轮
- 打开应用或网址
- Unicode 常用语直接上屏

支持**按前台应用切换配置**（例如浏览器里方向键=翻页，播放器里=快进后退）。

### 语音输入

语音页两种模式：

**模式 1 — 交给输入法识别（推荐，中文最准）**

```
遥控器话筒 → MoteDeck(解码) → WASAPI → CABLE Input
                                          ↓
输入法麦克风设为 CABLE Output ←───────────┘
语音键 ← 映射成输入法的语音快捷键（微信输入法 / 豆包输入法 / Win+H）
```

要点：MoteDeck 的输出端点必须选 **CABLE Input**，输入法的麦克风必须选 **CABLE Output**。这两个搞反了会"有录音但不出字"，是最常见的失败原因。

**模式 2 — 本地离线识别**

内置 SenseVoice 模型，断网可用，识别完成后直接把文字送进当前输入框，不依赖输入法。

### 注意

- 谷歌遥控器是第三方代工、存在多个批次，作者明确写了"不能保证所有版本都能用"。先在设备页确认能不能识别，识别不了直接去 Issues 反馈。
- 安装包未签名；作者自述代码几乎全部由 AI 辅助开发。介意的话走路线 B。
- 想校验安装包：发布页有 `SHA256SUMS.txt`，`Get-FileHash -Algorithm SHA256` 对比。

**另一个可参考的项目**：`zfdang/remote-buddy-windows`（GPL-3.0，C# / .NET 10）。Windows 版还在真机验收阶段，但它的 `docs/` 是目前中文资料里最完整的 ATVV 协议文档，自己实现时照着抄协议细节最省时间。

## 4. 路线 B：自己实现（分三层，可以只做前两层）

### 第 1 层：按键 —— 先搞清楚"能不能收到"

**坑 1：方向键和 OK 可能压根收不到键盘事件。**

G9N9N 的按键不是标准键盘码，而是 Consumer Control 页的 usage：

| 键 | Usage | Windows 是否映射成键盘键 |
|---|---|---|
| 上 / 下 / 左 / 右 | `0x0042` `0x0043` `0x0044` `0x0045` | **通常不映射** ← 关键 |
| 确认 OK | `0x0041` | **通常不映射** |
| 返回 Back | `0x0224` | 映射为 Browser_Back |
| 主页 Home | `0x0223` | 映射为 Browser_Home |
| 静音 / 音量± | `0x00E2` `0x00E9` `0x00EA` | 映射为音量键 |

也就是说：用 AutoHotkey 监听键盘，音量键、主页、返回能拿到，**方向键和 OK 大概率什么都收不到**。很多人卡在这一步以为遥控器坏了。

要把方向键读出来，必须用 **Raw Input** 读原始 HID 报文，而不是等键盘事件：

```c
// 注册 Consumer Control 页（0x0C），RIDEV_INPUTSINK 保证后台无焦点也能收
RAWINPUTDEVICE rid = { 0x0C, 0x01, RIDEV_INPUTSINK, hwnd };
RegisterRawInputDevices(&rid, 1, sizeof(rid));
```

然后在 `WM_INPUT` 里解 `RAWINPUTHEADER.hDevice` 区分是遥控器还是真键盘，再解 usage 码。

**坑 2：Windows 无法只屏蔽遥控器按键而保留键盘。**

低级键盘钩子 `WH_KEYBOARD_LL` 的 `KBDLLHOOKSTRUCT` **不包含设备句柄**，你在钩子里 return 1 会把物理键盘同一个键一起吞掉。

所以只有三种选择：

- **附加映射**（默认做法）：按键照常生效 + 额外触发动作 → 按音量键时"既输入文字又调音量"
- **驱动级按设备过滤**：装 Interception 驱动（`https://github.com/oblitum/Interception`），能按设备句柄区分，代价是装内核驱动
- 换用不冲突的键（推荐）——只映射 YouTube / Netflix / 信源键这类"按了也无所谓"的键

**第 1 层的最小可用产物**：本目录的 `remote-key-probe.ahk`。

```bash
# 装 AutoHotkey v2：https://www.autohotkey.com/
# 双击运行，然后逐个按遥控器按键，日志在本目录 remote-keys.log
```

跑完你就能得到一张"我这一支持不支持、每个键到底是什么码"的实测表，后面所有配置都基于它。

### 第 2 层：语音 —— ATVV 握手时序（顺序错了遥控器会卡死）

| Opcode | 名称 | 方向 | 报文 | 要点 |
|---|---|---|---|---|
| `0x0A` | GET_CAPABILITIES | 主机→遥控器 | `0A 01 00 00 03 03` | 连接后立刻发，协商能力 |
| `0x0B` | CAPS_RESP | 遥控器→主机 | `0B ver_hi ver_lo codec inter frame_hi frame_lo` | 校验 `codec==0x02`（16 kHz），取帧长 |
| `0x08` | START_SEARCH | 遥控器→主机 | `08` | **按下语音键的信号**，不走 HID |
| `0x0C` | MIC_OPEN | 主机→遥控器 | `0C 00` | 回它，同意开麦 |
| `0x04` | AUDIO_START | 遥控器→主机 | `04 inter codec sessionID` | **必须记住 `byte[3]` 的 SessionID** |
| `0x0A` | AUDIO_SYNC | 遥控器→主机 | `0A xx xx xx pred_hi pred_lo step` | 用预测值重置 ADPCM 解码器状态 |
| `0x0E` | MIC_EXTEND | 主机→遥控器 | `0E sessionID` | 每 5 秒发一次，否则长按约 10 秒被挂断 |
| `0x0D` | MIC_CLOSE | 主机→遥控器 | `0D sessionID` | 松手时发，必须带 SessionID |
| `0x00` | AUDIO_STOP | 遥控器→主机 | `00` | 收到后才能认为流结束 |

（`0x0A` 既是能力请求也是同步报文，靠方向区分。）

**四个必踩的坑：**

1. **不发 `0x0C` 就等音频** —— 遥控器根本不会开麦，你会以为是协议不通。
2. **不处理 `0x0A` AUDIO_SYNC** —— BLE 丢包后 ADPCM 的 predictor/stepIndex 会漂移，解码出来是刺耳白噪声。收到同步包立刻用 `pred`（大端 int16）和 `step` 覆写解码器内部状态。
3. **默认连接参数带宽不够** —— 实测默认只有约 32 包/秒，而 16 kHz ADPCM 需要约 50 包/秒，不请求低延迟就会断续、断字。Windows 上用 `BluetoothLEDevice.RequestPreferredConnectionParameters(BluetoothLEPreferredConnectionParameters.ThroughputOptimized)`；设置 `GattSession.MaintainConnection = true` 防止系统为省电挂起链路。
4. **音量太小** —— 遥控器麦克风是远场拾音，实测需要约 **+18 dB** 固定增益才够输入法识别，放大后叠加 80 Hz 高通滤波。

**时序（决定会不会吞首字/剪尾句）：**

```
按下：① 开一个 50~100ms 的 pre-roll 缓冲
      ② 注入输入法"开始录音"快捷键
      ③ 发 0x0C，等 0x04 拿 SessionID，开始把音频推进虚拟声卡

松开：① 先发 0x0D 关麦（不要立刻发结束键！）
      ② 继续收残余音频包，直到 0x00 或超时
      ③ 排空虚拟声卡队列（约 40~60ms）
      ④ 最后才注入"结束录音"快捷键
```

顺序反了的表现：说了"你好"出来"好"；或者说完整句被截掉最后两个字。

**技术选型建议**：Python 用 `bleak`（跨平台、上手快，够做 PoC）；要长期稳定用 C# + WinRT（`Windows.Devices.Bluetooth`），MoteDeck 和 remote-buddy 都是这条路。

### 第 3 层：虚拟声卡落地

VB-CABLE 是唯一现实选择（免费、WHQL 签名，不用自己签内核驱动）：

```
解码后的 PCM → WASAPI 写入 "CABLE Input"（这是播放设备）
                        ↓
输入法的麦克风选 "CABLE Output"（这是录音设备）
```

再配 Windows 11 自带听写（`Win+H`）或输入法语音键，就把链路闭环了。

## 5. 如果只是想"按一下就能说话"：最省事的做法

**不需要遥控器的麦克风。** 只要两样：

1. AutoHotkey 把麦克风键映射成 `Win+H`（或输入法语音快捷键）
2. 麦克风用电脑自带的 / 桌面 USB 麦

```ahk
; remote-key-probe.ahk 先跑一遍，确认麦克风键有没有键值；
; 如果麦克风键不出键值（大概率），就映射"主页"或"YouTube"这类能收到码的键。
```

代价：不用遥控器收音，拾音距离取决于你的电脑麦克风。收益：5 分钟完成，零依赖、零驱动、零虚拟声卡。**客厅远距离场景才值得上 ATVV 那条路。**

## 6. 验收清单

按顺序过，卡在哪一步就知道问题在哪层：

- [ ] 蓝牙配对成功，设备管理器出现 HID 键盘设备
- [ ] 音量键能调系统音量 → 说明 HID 链路通
- [ ] 跑 `remote-key-probe.ahk`，记录每个键的实际码
- [ ] 方向键 / OK 是否有码？没有 → 需要 Raw Input，别在键盘钩子上继续折腾
- [ ] 装好 VB-CABLE，系统声音设置里能看到 CABLE Input / CABLE Output
- [ ] MoteDeck（或自研程序）能识别设备并读到 ATVV 服务 `AB5E0001`
- [ ] 按语音键能看到包速率约 50 包/秒（低于 35 就是连接参数没调）
- [ ] 对着遥控器说话，虚拟声卡录音电平有波形
- [ ] 输入法实际转写出文字（这一步才算闭环）
